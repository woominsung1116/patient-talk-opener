# 환자 아바타 고품질화 — 현황과 다음 계획 (2026-11-10)

관련: `2026-07-25-avatar-realism-spec.md`, `tools/avatar_pipeline/README.md`
작업 브랜치: `avatar-photo-identity-wip` (main 미반영)

목표: 진료실 화면의 환자를 "게임 NPC"가 아니라 실제 한국인 환자처럼 보이게 한다.
**제약**: 문진(말하기·입모양·깜빡임·표정)과 신체진찰(자세 전환, 상의 걷기·하의 내리기,
부위 마커)이 지금처럼 동작해야 한다. 그래서 MPFB 메시·뼈대·ARKit 모프·의상 레이어는 유지하는
쪽으로만 바꾼다.

## 2. 발견한 파이프라인 버그 — 얼굴 개인차가 한 번도 적용된 적 없음

`upgrade_mpfb_morphs.py` 의 identity 루프는 `TargetService.set_target_value()` 를 쓰는데,
이 함수는 **이미 로드된 shape key 만 바꾸고 없으면 조용히 무시한다.** 그래서
`ASIAN_FACE`(동북아 형질)·`FACE_VARIATION`(개인차)·연령 골격이 배포된 아바타 전원에
적용되지 않았다. 로그의 `applied=N missing=0` 은 예외가 없었다는 뜻일 뿐이다.

- 새 `--face-fit` 경로는 `target_full_path()` + `load_target()` 으로 실제 로드한다(검증됨:
  재빌드 후 머리 경계·랜드마크 오차가 바뀜).
- **기존 identity 루프는 아직 고치지 않았다.** 고치면 검증 안 된 값이 18명 전원에게 한 번에
  들어간다. 아바타별로 사진 기준 얼굴을 맞추면서 함께 정리할 것.

## 3. 사진 기반 얼굴 실험 (`mh_m60` 한 명만)

생성 사진(실존 인물 아님) → 3D 아바타로 옮기는 흐름을 시험 중이다. 결과는 **아직 게임 품질이
아니다** — `qa/latest_compare.png` 좌(게임) / 우(기준 사진).

| 단계 | 방법 | 결과 |
|---|---|---|
| 기준 사진 | GPT 이미지 생성(정면) → 같은 인물 좌·우·뒤 생성 | 같은 인물로 일관되게 나옴 (`photo_identity/refs/`) |
| 얼굴형 | MediaPipe 랜드마크(사진 vs 아바타 정면 렌더) → MPFB 타깃 가중치 최소제곱 (깊이 변화 억제, 정수리 높이 제약 포함) | 랜드마크 오차 2.72 → 약 1.6~2.0 mm. 입술·코 생김새는 타깃 조합으로 표현 한계 |
| 피부 | 사진을 정면 투영해 UV 에 굽되, **눈꺼풀·입술은 원래 텍스처 유지**, 나머지는 사진의 고주파 디테일만 이식 | 깜빡임·표정에서 안 깨짐. 사진 그대로 덮으면 깜빡일 때 눈꺼풀이 찢어졌음 |
| 헤어 | 4면 실루엣의 비주얼 헐로 헤어 셸 생성 → 4면 사진 색 투영 → head 본에 리깅 (`--hair-mesh`) | 흰머리·윤곽은 사진을 따름. 헤어라인이 들쭉날쭉, 이마가 벗겨져 보임 |
| 움직임·탈의 | 메시·뼈대·모프·의상 레이어 불변 | 모프 67개 검증 통과. 최종본으로 발화·탈의 장면은 미확인 |

결론: **MPFB 얼굴에 사진을 입히는 방식은 한계에 가깝다.** 얼굴 생김새가 메시 형상을 따라가서
사진과 같은 사람이 되지 않는다.

### 재현 (프로토타입)

`tools/avatar_pipeline/photo_identity/` 의 스크립트는 작업 디렉터리 기준 상대경로
(`render.png`, `mesh.npz`, `fit/`, `../gen/`)를 가정한 **프로토타입**이다. `dump_identity_body.py`
에는 작업 당시 절대경로가 남아 있다. 정식 도구로 쓰기 전에 인자화해야 한다.

순서: `dump_head.py`(Blender, 정면 렌더+메시) → `landmarks.py` → `dump_identity_body.py`(Blender)
→ `solve_face_fit.py` → `assets/face_fit/<name>.json` → `batch_upgrade.py --only <name>`
→ `build_hair.py` → `assets/hair/photo_<..>/{hair.png,mesh.npz}` + `characters.json` 의
`hair_texture` → 재빌드 → `project_skin.py` → `frontend/public/avatars/skin/photo_<name>.webp`
→ `RealisticPatient.tsx` 의 `PHOTO_SKIN_VARIANTS` 에 등록.

## 5. 다음 계획

**방향 전환: 사진 → 3D 형상 생성 → MPFB 메시를 그 형상에 수축 포장(wrap).**
형상이 사진과 맞아야 텍스처가 맞는다. wrap 은 MPFB 정점 구조를 유지하므로 뼈대·모프·탈의·
진찰 부위가 그대로 산다. 일반적인 "자동 리깅 캐릭터"는 옷과 몸이 한 덩어리이고 표정 모프가 없어
이 게임에 바로 못 쓴다.

1. **3D 형상 생성 모델 선택**
   - TripoSG (MIT): 형상만 생성. 공식 스크립트는 CUDA 전용(`diso`, `device='cuda'`). 맥(MPS)
     이식 가능성 확인 중. 배경 제거는 RMBG-1.4(별도 라이선스) 대신 자체 마스크를 쓴다.
   - TRELLIS.2 (MIT, 일부 렌더 모듈 별도 라이선스): 리눅스 + NVIDIA 24GB 이상.
   - **Hunyuan3D-2 는 사용 불가** — 라이선스 적용 지역에서 한국·EU·영국 제외.
2. 정면 사진으로 머리(가능하면 상반신) 형상 생성 → 품질 판정 후 진행 여부 결정.
3. MPFB 머리 메시를 생성 형상에 wrap (얼굴 랜드마크 대응점 + 비강체 정합), 눈·입 내부는 기존 유지.
4. 4면 사진을 wrap 된 메시에 투영 → 피부·헤어 텍스처. 헤어라인은 생성 형상 기준으로 다시 잡는다.
5. 진료실에서 표정·발화·고개 움직임·탈의·진찰 마커를 캡처로 검증 → 통과 시 다른 환자로 확대.
6. 그 다음: 앉기·눕기 등 나머지 자세 전환도 무릎 세우기처럼 키프레임화.
