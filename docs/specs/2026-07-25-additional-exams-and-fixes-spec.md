## 1. 신규 술기 — 케이스 주소를 진찰할 수단이 없다

의학 리뷰 지적 B(3·4·5): 환자가 호소하는 증상을 **진찰할 항목 자체가 없어서**,
신체진찰 20점이 관련 없는 음성 소견 하나에 걸려 있는 케이스가 3개다.

### 1.1 손떨림검사 (`tremor_exam`) — 평가표 「손떨림검사」

```
① 양손을 앞으로 뻗게 한다
② 손등 쪽으로 손바닥을 최대한 젖힌 채 손가락을 넓게 펴게 한다
③ 자세를 유지한 채 최소 10초 이상 관찰한다
```

- **시진 술기라 부위 클릭이 없다.** `required_regions: []`.
- 완료 조건: 발화 지시 `do_tremor_check`(신규 인텐트) → 제스처 `hands_out` 발동 →
  **10초 이상 유지**해야 완료. 중간에 다른 도구를 고르면 취소.
  (평가표가 명시한 유일한 시간 조건이다. 청진 5초처럼 실제로 지켜지게 하라)
- 인텐트 키워드: "손을 뻗", "양손을 앞으로", "손 떨림", "손떨림", "손을 펴", "떨리는지"
  — 활용형 주의("뻗어보세요"/"뻗어 보세요"/"뻗으세요").

**붙일 케이스와 소견:**

| 케이스 | 소견 | 근거 |
|---|---|---|
| `weightloss_supplement_thyrotoxicosis_01` | 양손에 **미세한 빠른 떨림**(fine tremor)이 뻗은 자세에서 뚜렷 | 갑상선중독증의 전형 |
| `hyperthyroidism_01` | 동일 (fine tremor) | `hidden_facts.insomnia_tremor` 존재 |
| `herbal_fulminant_hepatitis_01` | **손목이 툭툭 떨어지는 퍼덕임(asterixis, flapping tremor)** — 간성뇌증 | `hidden_facts.confusion_progression`, `teaching_points[0]` |
| `alcohol_withdrawal_tremor_01` | 거친 떨림 (coarse tremor) | 케이스명이 tremor다 |

> ⚠️ **fine tremor와 asterixis는 완전히 다른 소견이다.** 갑상선은 빠르고 규칙적인 미세 떨림,
> asterixis는 자세를 유지하지 못하고 손목이 간헐적으로 떨어지는 **음성 근긴장(negative myoclonus)**이다.
> 소견 문구에서 이 둘을 섞지 마라. 이걸 구분하는 게 이 술기의 교육 목적이다.

**3D 연출**: `examGesture: 'hands_out'` 추가 — 환자가 양팔을 앞으로 뻗고 손가락을 편다.
케이스 소견에 따라 떨림 모션을 다르게 한다(fine = 빠른 소진폭 / asterixis = 간헐적 손목 낙하 / coarse = 느린 대진폭).
새 본 애니메이션을 만들지 말고 **기존 팔 본에 절차적 노이즈**를 얹어라.
`signs`에 `tremor_fine` / `tremor_asterixis` / `tremor_coarse`를 추가해 연출을 고른다.

### 1.2 간촉진 (`liver_palpation`) — 평가표 「간촉진」

```
① 침대에 눕혀 무릎을 세운 상태
② 복식호흡을 시킴
③ 왼손은 옆구리를 받치고
④ 오른손으로 갈비뼈 모서리 아래쪽에서 위쪽으로 압박하면서 간 끝을 확인
```

- `required_regions: ["ruq"]` — 기존 복부 4분면 시스템을 그대로 쓴다.
- prep 요구: `knee_flex`(기존) + `deep_breath`(흉부 스펙 §5에서 신설하는 인텐트를 공유)
  → `requires_prep: ["knee_flex", "deep_breath"]`. 미충족 시 완료는 시키되 `ratio *= 0.9` + 피드백.
- `must_precede`: 청진 → 타진 → 촉진 → 간촉진 순.

**붙일 케이스:**

| 케이스 | 소견 |
|---|---|
| `drug_induced_autoimmune_hepatitis_01` | 간이 우측 갈비뼈 아래 **2cm 정도 만져지고 가장자리가 무디며 눌렀을 때 불편감** |
| `herbal_fulminant_hepatitis_01` | **간이 만져지지 않고 오히려 작아진 느낌** — 전격성 간부전의 간 위축. 이게 나쁜 징후다 |

> ⚠️ 전격성 간부전에서 **간이 커지지 않고 줄어드는 것**이 예후가 나쁜 소견이다.
> "간이 크게 만져진다"로 쓰면 정반대를 가르친다.

### 1.3 하지 않을 것

머피징후·비장촉진·복수확인 등 나머지 평가표 술기는 **해당 케이스가 없으므로 만들지 마라.**
케이스 주소와 무관한 술기를 늘리면 학생이 "일단 다 해보기"를 학습한다.

## 2. 의학 리뷰 지적 수정 (9건)

### 2.1 [필수] 결막검사와 공막검사가 같은 항목으로 취급됨 (지적 #6)

`frontend/src/store.ts:512-516`:
```ts
do_conjunctiva: eyeItem ?? 'conjunctiva',
do_sclera:      eyeItem ?? 'sclera_exam',
```
`eyeItem`이 "케이스가 가진 눈 항목"이라, 빈혈 케이스에서 "**공막** 볼게요"라 해도 결막검사가 시행되고
간염에서 "**결막** 창백한지 볼게요"라 해도 공막검사가 시행된다. 평가표는 둘을 **별개 술기 행**으로 구분한다.

**수정**: `eyeItem` 폴백을 제거하고 인텐트와 항목을 1:1로 매핑한다.
케이스에 해당 항목이 없으면 기존 `doHeadNeckExam`의 안내(`"이 환자에게는 필요하지 않은 진찰이에요."`)를 띄운다.
"눈 좀 볼게요" 같은 **모호한 발화**만 케이스가 가진 항목으로 보내되, 이때는
`"결막을 볼까요, 공막을 볼까요?"` 로 되묻지 말고 그냥 케이스 항목으로 보내라(게임 진행이 막히면 안 된다).
`do_conjunctiva`/`do_sclera`처럼 **명시적인 발화는 반드시 그 항목으로만** 간다.

### 2.2 [필수] 우상복부 타진 소견이 의학적으로 틀림 (지적 #9)

`acute_flank_pain_urolithiasis_01` → `percussion.region_findings.ruq`:
> "우상복부는 정상 고창음이고, 간 탁음 범위도 정상입니다."

**우상복부 타진의 정상 소견은 간 위의 탁음**이다. 한 문장 안에서 고창음과 간 탁음이 충돌한다.
또 한 지점 타진으로 간 탁음 "범위"를 판정할 수 없다.

**수정 예**: `"우상복부는 갈비뼈 아래로 간 탁음이 들리고, 그 아래는 정상 고창음입니다."`
나머지 3분면(luq/rlq/llq)의 고창음 표현은 그대로 두어도 된다.

### 2.3 [필수] `tender_region`이 죽은 코드다 (지적 #1·#2)

`scoring.py:316-327`의 `tender_region` 로직이 어느 케이스에서도 발동하지 않는다.
평가표 복부타진⑤·복부촉진⑤·CVA는 **"아픈 부위는 가장 마지막에"**를 요구한다.

`acute_flank_pain_urolithiasis_01`에 설정한다:
- `cva_tenderness`: `"tender_region": "flank_r"` — 무증상 좌측을 먼저 두드려 비교한 뒤 아픈 우측
- `percussion` / `palpation`: 주소가 우측 옆구리~등이므로 복부 4분면 자체엔 압통이 없다.
  **억지로 설정하지 마라.** 소견이 "4분면 모두 음성"인데 tender_region을 두면 모순이다.

설정 후 실제로 감점이 발동하는지 E2E로 확인하라(지금까지 한 번도 실행된 적 없는 코드다).

### 2.4 [필수] 하지 않은 설명·동의가 로그에 남는다 (지적 #8)

`store.ts:505-507`이 `request_exam`("침대에 누우실까요") 한 마디로 `explain_consent`를 기록하고,
서버가 `"진찰 목적과 방법을 설명하고 동의를 구했습니다."`를 돌려준다. 학생은 "누우세요" 한 줄이면
충분하다고 학습한다. PPI 6-2는 이미 대화 정규식으로 엄격화됐지만 **로그 문구가 여전히 거짓**이다.

**수정**: `request_exam`으로 자동 기록되는 항목의 finding을 사실에 맞게 바꾼다 —
`"진찰을 하겠다고 알리고 환자의 동의를 얻었습니다."` 정도로. 그리고 목적·방법·불편감까지 설명한 경우에만
PPI 6-2가 pass되는 현 동작은 유지한다(이미 맞다).
진행 흐름을 막지 마라 — 기록 자체는 계속 남겨야 진찰 단계로 넘어간다.

### 2.5 [두경부 스펙에서 처리] 지적 #7 (갑상샘 좌우 엽 순차 촉진)

`2026-07-25-headneck-exam-fidelity-spec.md` §3·§5·§6에서 다룬다. 여기서 중복 구현하지 마라.

## 3. 진찰 도구 3D 에셋

### 3.1 설압자 — 현재 절차적 도형

`ClinicScene.tsx`의 `OralExamRig`가 설압자를 `boxGeometry`(0.017×0.115×0.0022) + 끝단 `cylinderGeometry`로
직접 그린다. 사용자가 에셋으로 바꾸길 원한다.

**작업 순서:**
1. 무료 + 상업 이용 가능한 설압자(tongue depressor) 3D 에셋을 찾는다.
   기존 에셋들과 같은 기준으로 라이선스를 거른다 (CC0 우선, CC-BY는 출처 표기 조건).
   기존 출처: Poly Haven(CC0), ambientCG(CC0), Sketchfab CC-BY.
2. **적합한 에셋을 못 찾으면 억지로 받지 말고** 절차적 형상을 개선하라 —
   설압자는 나무 막대라 형상 자체는 단순하다. 지금 부족한 건 형상이 아니라 **표면**이다:
   - 모서리 베벨(지금은 각진 박스)
   - 나뭇결 텍스처 + 적절한 roughness (지금은 단색 `#d8b98a`)
   이쪽이 저품질 에셋을 받는 것보다 결과가 낫다면 그렇게 하고, **판단 근거를 보고에 적어라.**

### 3.2 펜라이트 — 형상이 아예 없다

`OralExamRig` 주석: `"펜라이트 조명 — 막대는 손에 가려진 설정, 입안을 비추는 빛만 표현"`.
즉 **펜라이트 실물이 없다.** 평가표 구강검사 ③이 "펜라이트를 비추면서"를 요구하므로,
학생이 펜라이트를 쓰고 있다는 게 화면에 보여야 한다. 설압자와 같이 처리하라.

### 3.3 라이선스 표기

새 에셋을 받으면 `frontend/public/models/CREDITS.md`(없으면 생성)에 출처·라이선스를 기록하고,
CC-BY면 **앱 화면에도 표기**해야 한다. 흉부 스펙 §8에서 만드는 출처 표기 화면에 함께 넣어라.
