# MVP 범위 확정 (2026-07-25) — 이 문서가 우선순위의 기준이다

사용자 지시: "일단은 **필요한 신체진찰과 질병으로 MVP**를 만들고 나중에 늘리면 된다."
1순위 = **환자 자연스러움 + 신체진찰 완성도**. 그 외는 전부 뒤로.

**다른 스펙 문서들은 이 범위 안에서만 적용한다.** 범위 밖 케이스에 술기를 추가하지 마라.

---

## 1. MVP 케이스 6개

| # | 케이스 | 진찰 | 이 케이스가 가르치는 것 |
|---|---|---|---|
| 1 | `acute_flank_pain_urolithiasis_01` | 복부 청진·타진·촉진(4분면, 얕게/깊게) + **CVA 양측** | 편측 CVA 압통, 복막자극징후 없음 → 충수염 감별 |
| 2 | `iron_deficiency_anemia_01` | **결막검사**(양안) + **구강검사**(혀·인두) | 결막 창백, 위축성 설염·구각염 |
| 3 | `hyperthyroidism_01` | **갑상샘 시진·촉진**(좌우엽) + **손떨림**(fine) + **심장청진**(빈맥) | 미만성 종대 + 갑상선중독 증상 |
| 4 | `weightloss_supplement_thyrotoxicosis_01` | **3번과 동일한 술기 세트** | **갑상샘만 정상** → 외인성 갑상선중독증 감별 |
| 5 | `herbal_fulminant_hepatitis_01` | **공막검사**(양안) + **손떨림**(asterixis) + **간촉진** | 황달 + 간성뇌증 + **간 위축**(나쁜 징후) |
| 6 | `panic_attack_01` | **심장청진**(4판막) + **폐청진** | **정상임을 확인하는 것**이 진단의 핵심 |

### ⚠️ 케이스 간 우선순위 — 1번(복통)이 최우선

사용자 지시 (2026-07-25): **"복통쪽이 일단 최우선이야, 저 6개 케이스 중에서도."**

`acute_flank_pain_urolithiasis_01`이 **완성 기준 케이스**다. 이유:
- MVP 유일한 복통 케이스이고, 복부 4분면 청진·타진·촉진(얕게/깊게) + 양측 CVA로 **술기가 가장 무겁다**
- 유일하게 처음부터 `education_items`를 갖고 있어 CPX 4축이 완결돼 있다
- 지금까지 잡힌 치명적 3D 결함이 **전부 복부 진찰**이다(청진기 소매·촉진 손·하복부 마커·옆구리 마커)

**작업 규칙**: 각 웨이브에서 복부 경로를 먼저 완성·검증한 뒤 두경부·흉부로 넘어간다.
수정 라운드가 부족하면 **두경부·흉부는 덜 다듬어진 채 남겨도 되지만, 복부가 깨진 채 남는 것은 허용하지 않는다.**

### 이 조합을 고른 이유
- **진찰 모달리티 전수 커버**: 복부 4분면 / CVA 양측 / 결막 / 공막 / 구강 / 갑상샘 시진·촉진 / 손떨림 / 간촉진 / 심장 4판막 / 폐야
- **감별 구조 2쌍**:
  - 3 ↔ 4: 같은 술기, 갑상샘 소견만 다름 → 술기 하나가 진단을 가른다
  - 6: 3·4의 빈맥에 대한 **정상 심음 대조군**
- **소견 대비 3종**: 손떨림이 fine(갑상선) / asterixis(간부전) / 정상으로 갈린다

## 2. MVP에서 하지 않는 것

| 항목 | 상태 |
|---|---|
| 나머지 11개 케이스 | **문진만** 유지. `exam_items` 추가하지 마라. 기존 legacy 채점으로 정상 동작해야 한다(회귀 금지) |
| `drug_induced_autoimmune_hepatitis_01` | 5번과 소견 중복(공막 황달) → MVP 제외. 기존 상태 유지 |
| 머피징후·비장촉진·복수확인·시야·청력·이경·림프절·근력·감각·반사·보행 등 | 평가표에 있어도 **해당 케이스가 없으므로 만들지 마라** |
| 흉부 타진·흉곽팽창·성음진탕 | 흉부는 **청진만**. 나머지는 나중에 |
| 모바일·태블릿 대응 | 보류 |
| 오라클 배포 / STT 교체 | 보류 |
| 흉통 신규 케이스 | 만들지 마라. 6번(공황장애)이 흉부 청진을 커버한다 |

> 주소(chief complaint)와 무관한 술기를 늘리면 학생이 "일단 다 해보기"를 학습한다.
> **케이스가 요구하지 않는 술기는 MVP에 넣지 않는다.**

## 3. MVP 완성 조건

각 케이스가 **CPX 4축을 모두** 갖춘다: 병력청취 / 신체진찰 / 환자교육 / PPI.

### 3.1 지금 비어 있는 것 — `education_items`

현재 `education_items`가 있는 케이스는 **요로결석 1개뿐**이다.
나머지 5개는 `scoring_weights.patient_education: 0`으로 임시 처리돼 있다.

MVP에서는 5개 케이스에 `education_items`를 추가하고 배점을 되돌린다:

```json
"scoring_weights": { "history_taking": 40, "physical_exam": 30, "patient_education": 10, "ppi": 20 }
```
(요로결석과 동일 배점. 두경부 위주 케이스도 술기 수가 늘어나 30점이 타당해진다)

`education_items` 구조는 요로결석 케이스를 그대로 본뜬다:
`diagnosis`(evidence_options 포함) / `test_plan_*` / `tx_*` / `complication`.

> 진단 근거(evidence_options)에는 **그 케이스에서 실제로 얻을 수 있는 소견만** 넣어라.
> 학생이 시행하지 않은 진찰의 소견을 근거로 고를 수 있으면 안 된다.

### 3.2 배점 재조정 시 확인
`_compute_weighted`가 `patient_education: 0`에서도 안전했듯, 10으로 올린 뒤에도
`education_items`가 없는 **범위 밖 케이스**는 여전히 legacy 경로로 가야 한다. 회귀 확인 필수.

## 4. 작업 순서

| 웨이브 | 내용 | 상태 |
|---|---|---|
| ① | 신체진찰 채점 연결 + 4분면·좌우 술기 | ✅ 완료 (E2E 9/9) |
| **A** | ② 진찰 부위 본기준 정합 ‖ ③ 아바타 자연스러움 | 🔄 진행 중 (3D 파일만 점유) |
| **B1** | 케이스 6개 데이터(exam_items + **education_items** + 배점) ‖ 백엔드(인텐트·채점) | 🔄 A와 병렬 (3D 안 건드림) |

## 4.5 보류 — 안구운동검사 ("손가락을 따라오세요")

사용자 제안(2026-07-25), **MVP 이후로 미룸**(사용자 확인). 잊지 않도록 근거와 함께 남긴다.

**기계장치는 이미 있다.** `RealisticPatient.tsx`의 시선 제어(`gazeGoalX`/`gazeGoalY` + 감쇠 보간)가
`eyes_up` 제스처에 쓰이고 있다. 좌·우·아래로 확장하고 H자 경로를 따라 애니메이션하면 된다. 비용이 크지 않다.

**평가표 근거**: 독립 술기 행이 없다. HINTS 검사 하위의
"2. 안진을 관찰하였다 — ① 머리는 고정한 채 정면을 보게 한다 ② **좌·우 상·하로 시선만 따라오게 한다**"가 유일하다.
(시야검사는 "편 손가락이 몇 개인지"라 다른 술기다 — 혼동하지 말 것.)

**붙일 곳 — 둘 중 하나가 필요하다. 지금은 둘 다 없다:**

| 경로 | 내용 | 비고 |
|---|---|---|
| (a) 갑상선 케이스 확장 | 그레이브스 **안병증**(안검 지체·안구돌출)을 병력·`hidden_facts`·소견에 정식 추가 | **감별이 강해진다** — 안병증은 그레이브스에만 있고 외인성 갑상선중독증엔 없다. 지금 감별이 갑상샘 소견 하나에만 걸려 있는데 근거가 둘이 된다 |
| (b) 어지럼 케이스 신규 | HINTS 3종(head impulse · 안진 · test of skew) 전체 | 평가표를 그대로 따를 수 있다. 케이스 신규 제작 필요 |

> ⚠️ **케이스에 없는 소견을 진찰로만 끼워넣지 마라.**
> 현재 `hyperthyroidism_01`은 눈 관련 언급이 **0건**이다(주소 = 두근거림 + 체중감소).
> 여기에 안검 지체 소견만 붙이면 병력에 없는 증상을 지어내는 것이 된다.
> (a)를 택한다면 **케이스 자체를 확장**해야 한다 — 병력·은폐구조·교육항목까지 함께.

## 5. 온톨로지 — 필드만 미리 만들고 연결은 하지 않는다

**연결 작업은 나중에 로컬 LLM이 한다.** 이 저장소에서 코드 값을 채우거나 매핑 로직을 만들지 마라.
다만 **필드는 미리 넣어둔다** — 비워두는 비용이 0이고, 나중에 채우는 쪽이 스키마 변경 없이 붙일 수 있다.

**B1 종료 직후** 케이스 스키마와 `validate_case.py`에 아래를 추가한다 (B1이 케이스 파일을 잡고 있어 그 뒤에):

```jsonc
// diagnosis_options 각 항목, exam_item, education_item 에 공통으로
"codes": {
  "icd11": null,      // 질병
  "kcd": null,        // 한국표준질병사인분류
  "hpo": null,        // 소견·표현형
  "snomed": null      // 임상 개념 전반
}
```

규칙:
- **전부 nullable.** 값이 없어도 validate를 통과해야 한다. 지금은 전부 null이다.
- 값을 **추측해서 채우지 마라.** 틀린 코드는 빈 코드보다 나쁘다.
- 매핑 로직·조회 코드를 만들지 마라. 필드 선언까지가 이 저장소의 범위다.

> 참고: 나중에 온톨로지를 붙이면 지금 케이스 JSON에 프로즈로 흩어져 있는 소견을
> 소견 카탈로그로 정규화하는 리팩터링이 자연스러워진다. 그 설계는 MVP 6개가 완성된 뒤에 판단한다
> (케이스가 없는 상태에서 설계한 카탈로그는 거의 확실히 틀린다).
