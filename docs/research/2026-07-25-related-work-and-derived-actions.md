# 선행연구 검토와 도출 과제 (2026-07-25)

사용자가 제시한 논문 2편을 검토하고, 우리 프로젝트에 차용할 것과 차용하지 않을 것을 정리한다.
**이 문서는 구현 스펙이 아니라 근거·판단 기록이다.** 실제 작업은 각 항목의 "반영 위치"를 따른다.

## 논문 1 — 메타버스 OSCE (한국의학교육 2026)

> Huh YJ, Shin JS, Yoon N, Kim JW, Kim DH, Kim C, Jeong S, Yoon Y, Shin S, Kong HJ, Myung SJ.
> **Metaverse-based objective structured clinical examinations: an exploratory approach to advancing clinical competency assessment.**
> *Korean J Med Educ.* 2026;38(2):139-148. doi:10.3946/kjme.2025.151. PMID 42157374.

우리와 **같은 문제·같은 시기·같은 나라**의 연구다. LLM 가상환자 + 3D 진료 환경 + 신체진찰.

### 그들이 한 것
- LLM을 **RAG(벡터 DB + 의미 유사도 검색)**로 연결해 질문에 맞는 케이스 정보만 프롬프트에 주입
- 아바타에 임상 징후 표시(공막 황달, 근감소 사지, 복부 팽만)
- 신체진찰: 시진·청진·타진·촉진. **손 제스처 인식**(컨트롤러 아님), 부위별 장음, **부위에 따라 다른 타진음**(복수 반영), 촉진 시 **접촉 지점 압박 시각 피드백**
- 채점: 체크리스트 대신 **전문가 총괄평정척도**, 상호작용 자동 기록·분석
- 전문가 10인 합의로 시나리오 4개 선정

### 차용 — 확정
| 항목 | 내용 | 반영 위치 | 우선순위 |
|---|---|---|---|
| **케이스 선정 기준** | "**표준화 환자로 일관되게 재현하기 어려운 소견**"을 우선 채택. 그들은 황달+복수+복통을 이 이유로 선정. 가상환자의 비교우위가 여기 있다 | `MVP-scope.md` 확장 기준에 명문화 | MVP 이후 확장 시 |
| **접촉점 압박 피드백** | 촉각이 없으므로 "닿았다/누르고 있다"를 눈으로 알려야 한다 | `first-person-exam-feel-spec.md` §3 | **B2** |
| **RAG 구조** | 케이스 전체를 프롬프트에 넣는 현재 방식은 질병 수백 개에서 무너진다. 벡터 DB에서 필요한 사실만 검색해 주입 | 미정 — MVP 이후 | 중 (확장성) |

### 차용하지 않음 — 근거
| 항목 | 이유 |
|---|---|
| 자세 제어 **버튼 패널** | VR 컨트롤러 어포던스다. 실제 CPX에서 의사는 버튼이 아니라 **말로** 지시한다. 우리 음성 방식이 교육적으로 옳다 |
| 복부 진찰 **장갑** | 그림엔 파란 장갑이 있으나 한국 CPX 평가표는 복부 진찰에 장갑을 요구하지 않는다(요구하는 것은 손위생). 장갑은 점막·체액 접촉 술기용 |
| **진료실 배경** | 그들 환경은 흰 박스 수준이다. 우리 3D 진료실이 훨씬 낫다. 단순화하면 퇴보 |
| VR 양손 트래킹 | 우리는 브라우저·마우스. 흉내내지 말고 도구·부위 상호작용에서 손이 자연스럽게 보이는 데 집중 |

### 우리가 이미 더 나은 지점
- **촉각 부재 문제**: 그들은 "압통·경직·반발통을 재현하지 못한다"를 주요 한계로 남겼다.
  우리는 **환자 반응 채널**(`reaction: {emotion, line, intensity}` → 표정 변화 + "악! 거기가 아파요" + 화면 진동)로 우회한다.
  실제 임상에서도 압통은 손끝이 아니라 환자의 얼굴과 말로 확인한다. 햅틱 장비를 기다리는 것보다 타당하다.
- **접근성**: 그들의 한계 중 하나가 "고성능 컴퓨팅·안정적 인터넷 의존"(메타버스 클라이언트/헤드셋). 우리는 브라우저에서 돈다.
- **부위별 타진음**: 그들도 같은 것을 했다 → 방향 확인. 우리는 2026-07-25에 자체 합성으로 5종 구현 완료.

### 그들이 남긴 공백 = 우리 기회
저자들이 명시: 효과 입증을 위해 설계된 연구가 **아니고**, 학습자 피드백을 받지 않았으며, 표준화 환자와 비교하지 않았다.
→ 우리가 학습자 피드백과 SP 비교를 하면 그 공백을 메운다.

## 논문 2 — LLM OSCE 전사 채점 (arXiv 2024)

> Shakur AH, Holcomb MJ, Hein D, Kang S, Dalton TO, Campbell KK, Scott DJ, Jamieson AR.
> **Large Language Models for Medical OSCE Assessment: A Novel Approach to Transcript Analysis.**
> arXiv:2410.12858 (2024-10-11). UT Southwestern Medical Center.

### 그들이 한 것
- **실제 OSCE 영상 2,027건**(2019–2022) → Whisper-v3 전사 → LLM 채점
- 채점 항목: "학생이 환자 병력을 요약했는가" (의사소통 루브릭)
- 기법: zero-shot CoT, RAG, 다중모델 앙상블
- 결과: **GPT-4가 인간 채점자와 Cohen's κ = 0.88**. 오픈소스 모델도 비용효율적 배포 가능성
- 실패 조건과 배포 베스트프랙티스 제시

### 이것이 바꾸는 판단
그동안 우리 원칙은 "**점수는 전부 rule-based, LLM은 서술만**"이었다(LLM이 죽어도 게임이 돌게).
이 논문은 **의미 판단 채점이 실제로 신뢰할 만하다는 실증**을 준다. 원칙을 버릴 필요는 없고, **2단 구조**로 확장하면 된다.

### 도출 과제 A — 2단 채점 (MVP 이후)
| 단 | 대상 | 동작 |
|---|---|---|
| 1단 (규칙) | 기계적으로 검증 가능 — 손위생 선행, 진찰 순서, 부위 완수, 어려운 용어, 한 번에 여러 질문 | 현행 유지. **항상 동작** |
| 2단 (LLM 판정) | 의미 판단 — 공감(1-4), 무비판적 수용(1-5), 되묻기(2-5), 깔때기(2-6), 요약(5-3), 맥락 이어가기(5-4), 기억하기 쉽게(4-5) | LLM 있으면 사용, 없으면 현행 정규식 폴백 |

리포트에 **어느 단으로 매긴 항목인지 표시**한다. 학생이 "기계가 확실히 본 것"과 "AI 판단"을 구분할 수 있어야 한다.

정규식이 원리적으로 못 잡는 예 — PPI 5-3(그들이 테스트한 바로 그 항목):
```python
setr("5-3", _count_text(dialogue, r"그러니까|정리하면|정리해|지금까지 말씀|말씀을 정리") >= 2)
```
"정리하면"이라는 **단어가 있는지**만 본다. 실제 요약 여부는 모른다.
표현을 안 쓰고 제대로 요약하면 탈락하고, 표현만 쓰고 요약을 안 하면 통과한다.

### 도출 과제 B — 검증셋 (신뢰도의 전제)
현재 우리 PPI 채점이 인간 채점자와 얼마나 일치하는지 **측정된 바 없다.**
30세션 정도를 손으로 채점해 기준셋을 만들고 κ를 산출한다. 논문 2가 한 것이 정확히 이것이고,
논문 1이 **하지 않은 것**도 이것이다. 나중에 논문·사업 어느 쪽으로 가든 이게 신뢰의 근거가 된다.

### 도출 과제 C — STT 선택 뒷받침
그들은 **Whisper-v3**로 실제 임상 면담을 전사했다.
오라클 배포 시 MLX(애플 실리콘 전용) 대체 후보로 검토 중인 faster-whisper 노선의 실사용 근거가 된다.
→ `MVP-scope.md`의 보류 항목(STT 교체) 참고.

## 즉시 고칠 결함 — PPI 2-6 깔때기 판정 오류

논문 검토 중 발견. **논문과 무관하게 명백한 버그다.**

`backend/app/services/ppi_evaluator.py`:
```python
open_q  = _any_text(dialogue, r"어떤|어떻게|어디|무엇|왜|어떠|얼마나")
closed_q = _any_text(dialogue, r"있나요|없나요|있으세요|없으세요|하나요|인가요|맞나요|드세요\?")
setr("2-6", open_q and closed_q)
```

**둘 다 존재하는지만 본다.** 깔때기식 질문은 "개방형으로 넓게 물은 **뒤** 폐쇄형으로 좁혀가는" **순서**가 핵심인데
순서를 보지 않는다. 폐쇄형만 계속하다 마지막에 개방형 하나를 던져도 통과한다.

**수정 방향**: 첫 개방형 질문의 턴 인덱스 < 마지막 폐쇄형 질문의 턴 인덱스 를 요구한다.
(더 엄밀히는 개방형 구간이 폐쇄형 구간보다 앞서는지를 보지만, 턴제 대화에서는 위 조건으로 충분하다)

> 이 항목은 2단 채점의 2단(LLM 판정) 대상이기도 하다. 다만 순서 검사는 규칙으로도 정확히 가능하므로
> **1단에서 먼저 고치고**, 2단 도입 시 LLM 판정과 교차 검증한다.
