# 환자 말문 열기 — 기술 보고서

음성 기반 3D CPX(임상수행평가) 시뮬레이터

---

## 1. 무엇을 만들었나

의과대학생이 **3D 가상 환자와 음성으로 문진하고, 화면에서 직접 신체진찰을 수행하는** 웹
시뮬레이터다. 브라우저만 있으면 되고 설치가 필요 없다.

기존 CPX 실습의 병목은 **표준화 환자(SP) 섭외 비용**과 **피드백의 주관성**이다. 이 시스템은
반복 연습을 무제한으로 제공하고, 채점 근거를 항목 단위로 남긴다.

현재 케이스 17종(요로결석·갑상선기능항진증 등), CPX 평가표 4축으로 채점한다.

---

## 2. 진료 한 판이 어떻게 흘러가나

```
증례 선택
   ↓
진료 접수증        제시문 + 활력징후 제시
   ↓
① 문진             마이크로 질문 → 환자가 표정·자세·말로 반응
   ↓                 신뢰도가 오르면 숨겨둔 병력이 열린다
② 신체진찰         "복부를 촉진하겠습니다" 라고 말하면 전환
   ↓                 환자가 눕고, 옷을 걷고, 3D 부위를 눌러 소견을 얻는다
③ 진단·검사        진단명 입력 + 시행할 검사 선택
   ↓
④ 환자교육         진단 설명·검사 계획·치료·합병증
   ↓
리포트             4축 점수 + 놓친 항목 + 신뢰도 곡선
```

각 단계가 **다음 단계의 입력이 된다.** 문진에서 못 얻은 정보는 진찰로도 안 나오고, 진찰을
안 하면 진단 근거가 부족하다고 채점된다.

## 3. 한 번의 발화가 처리되는 경로

학생이 말을 한 번 할 때 시스템 안에서 벌어지는 일이다. 5단계를 거친다.

```
🎤 "요즘 잠은 잘 주무세요?"
   │
   ① 음성인식(STT)          음성 → 텍스트
   │
   ② 의도 분석              텍스트 → 구조화된 의도
   │                         { intent: ask_sleep, empathy: false, pressure: false }
   │
   ③ 환자 상태 갱신          신뢰도·불안·친밀도를 규칙으로 계산
   │                         숨은 병력 해금 조건을 검사
   │
   ④ 대사 생성              환자 페르소나로 LLM이 답변 작성
   │
   ⑤ 표현                   3D 환자가 표정·자세로 반응 + 음성합성(TTS)
```

### ② 의도 분석 — 무엇을 물었는지 알아내기

"언제부터 아프셨어요", "증상이 시작된 게 언제인가요", "며칠 됐어요" 는 표현이 다르지만
전부 **발병 시점을 묻는 질문**이다. 이걸 `ask_onset` 같은 하나의 의도로 묶는다.

동시에 **말투**도 분류한다. 공감했는가, 압박했는가, 민감한 질문을 배려 없이 던졌는가.
이건 뒤에서 PPI 점수와 환자 반응에 쓰인다.

여기서 **규칙과 LLM을 함께 쓴다.** LLM이 "갑상샘을 만져보겠습니다"를 일반 촉진으로
뭉뚱그리는 경우가 있는데, 이런 구간은 키워드 규칙이 더 정확하므로 규칙이 LLM 결과를
덮어쓴다.

### ③ 환자 상태 갱신 — 마음이 열리고 닫히는 규칙

환자는 **신뢰도·불안·친밀도** 세 수치를 갖는다. 발화의 성격에 따라 결정론적으로 움직인다.

| 학생의 발화 | 신뢰도 | 불안 | 친밀도 |
|---|---|---|---|
| 공감 표현 | +8 | −5 | +8 |
| 압박·추궁 | −10 | +12 | −6 |
| 민감한 질문을 공감 없이 | −6 | +10 | −5 |
| 성급한 진단 단정 | −5 | +8 | — |

**같은 질문을 반복하면 점수를 다시 주지 않는다.** 공감 표현을 도배해서 신뢰도를 올리는
꼼수도 상한으로 막았다.

### ③-2 숨은 병력이 열리는 조건

케이스마다 **처음엔 말하지 않는 정보**가 심어져 있다. 환자가 먼저 꺼내지 않는 것들이다.

```
예) 갑상선기능항진증 케이스의 숨은 정보

  "불면과 손떨림"
     열리는 조건 ─ 의도: ask_sleep (수면을 물어봐야 함)
                  신뢰도: 35 이상
                  공감 필요: 아니오
     열렸을 때 ─ "밤에 잠이 잘 안 오고, 손이 미세하게 떨려서
                  회의 때 커피잔을 못 들겠다"
     못 열었을 때 ─ "잠이야 뭐... 다들 못 자잖아요."
```

세 조건을 **전부** 만족해야 열린다.

1. **맞는 질문을 했는가** — 수면을 안 물으면 이 정보는 절대 안 나온다
2. **신뢰도가 충분한가** — 라포 없이 캐물으면 얼버무린다
3. **공감이 필요한 정보인가** — 민감한 항목은 공감이 선행돼야 한다

그래서 **질문 목록만 외워서는 만점이 안 나온다.** 순서와 태도가 정보 획득량을 바꾼다.
이게 이 시뮬레이터가 체크리스트 훈련과 다른 지점이다.

### ④ 대사 생성

LLM이 환자 페르소나로 답을 쓴다. 페르소나에는 성격·말투·현재 통증 수준이 들어간다
(예: *"통증 때문에 말이 짧고 자주 끊긴다"*).

여기서 **검증 단계가 하나 더 있다.** 규칙 엔진이 "이번 턴에 불면 정보가 열렸다"고 판정했는데
LLM 대사에 그 내용이 빠져 있으면, 대사를 다시 생성한다. **규칙이 정답이고 LLM이 거기에
맞춰야지, 그 반대가 아니다.**

### ⑤ 표현

의도 분석이 뽑은 감정으로 3D 환자의 표정·자세가 바뀌고, 대사가 음성으로 합성된다.

---

**진찰 발화도 같은 경로를 탄다.** "복부를 촉진하겠습니다"는 `do_palpate` 의도로 분류되고,
케이스가 그 술기를 가지고 있으면 진찰 단계로 전환되면서 환자 자세와 의복까지 함께 바뀐다.

---

## 4. 설계 원칙 — "규칙이 결정하고, LLM은 해석한다"

LLM에 **채점이나 상태 전이를 맡기지 않는다.** LLM의 역할은 두 가지뿐이다.

1. 학생 발화의 **의도 분류**
2. 환자 **대사 생성**

신뢰도 변화·정보 해금·점수는 전부 결정론적 규칙이 처리한다.

이유는 **재현성**이다. 같은 학생이 같은 질문을 했을 때 점수가 달라지면 평가 도구로 쓸 수
없다. 또한 LLM이 오분류해도 규칙이 방어한다 — 키워드가 더 정확한 구간에서는 규칙이 LLM
결과를 덮어쓴다.

같은 이유로 LLM 엔진을 **교체 가능한 구조**로 두었다(로컬 Ollama / Codex / Gemini).
엔진이 바뀌어도 채점 결과는 바뀌지 않는다.

---

## 5. 신체진찰이 도는 방식

버튼이 없다. 실제 CPX처럼 **말로 선언**하고 **손으로 수행**한다.

```
"복부를 촉진하겠습니다"
   ↓
진찰 단계로 전환 — 환자가 눕고, 상의를 걷어 복부를 노출한다
   ↓
학생이 3D 복부 4분면을 하나씩 꾹 누른다
   ↓
부위별 소견 반환 — "우상복부는 부드럽고 압통이 없습니다"
   ↓
4분면을 전부 찍어야 항목 완료 (촉진은 얕게→깊게 2회차)
```

화면에 진찰 도구 버튼이나 준비 버튼은 없다. 무엇을 해야 하는지 알려주지 않는 것이
시험이기 때문이다. 학생의 발화가 곧 술기 선언이다.

진찰 **순서**도 채점한다. 압통 부위를 먼저 누르면 환자가 방어해 나머지 진찰이 부정확해지므로,
아픈 곳은 마지막에 진찰해야 감점이 없다.

손위생·설명동의·가려주기 같은 준비 동작도 별도 항목이다. 학생이 말로 지시해야 한다.

## 6. 환자를 "살아 있게" 만드는 부분

임상 판단의 대상이 되는 신호는 장식이 아니라 **평가 항목의 일부**다. 그래서 물리적으로 맞게
구현했다.

- **호흡** — 자세에 따라 숨 쉬는 곳이 다르다. 누우면 배가, 앉으면 흉곽이 움직인다.
  호흡수는 케이스 활력징후에서 가져온다. 복부 진찰이 누운 자세라 학생이 봐야 할 배가
  실제로 오르내린다.
- **통증** — 신산통 같은 파고를 표정·자세·호흡이 함께 탄다. 배를 감싸 쥐고 웅크리는
  방어자세, 얕고 빠른 호흡이 같은 신호로 움직인다.
- **얼굴** — ARKit 표정 모프 67종. 감정 상태와 발화가 구동한다.
- **안색** — 황달·결막 창백을 색으로 판정할 수 있어야 하므로, 톤매핑과 해상도 하한을
  그 기준으로 잡았다.

## 8. 채점은 어떻게 하나

CPX 평가표를 그대로 4축으로 구현했다. 배점은 케이스마다 다르게 줄 수 있고, 아래는 표준
배분이다.

```
총점 = 병력청취(40) + 신체진찰(30) + 환자교육(10) + 환자의사관계(20)
```

각 축은 **"얼마나 했나"를 0~1 비율로 먼저 구하고, 거기에 배점을 곱한다.**

### 8.1 병력청취 — 필수 문항을 몇 개 물었나

케이스마다 **반드시 물어야 할 항목**이 정해져 있다(발병 시점, 방사통, 동반 증상, 복약력…).
학생 발화의 의도가 분류될 때마다 해당 항목에 체크가 찍힌다.

```
점수 = 40 × (물어본 필수 문항 수 ÷ 전체 필수 문항 수)
```

같은 내용을 여러 번 물어도 한 번으로 센다. 표현이 달라도 의도가 같으면 인정된다
("언제부터 아프셨어요" = "증상이 시작된 게 언제인가요").

### 8.2 신체진찰 — 시행 여부 + 순서

각 진찰 항목에 배점이 붙어 있고, **완료한 항목의 배점 합**이 기본 점수가 된다.

```
기본 비율 = 완료한 항목 배점 합 ÷ 전체 항목 배점 합
```

여기에 **감점 배수**가 곱해진다. 술기를 했느냐만이 아니라 **제대로 된 순서로 했느냐**를 보기
때문이다.

| 위반 | 배수 | 이유 |
|---|---|---|
| 손위생을 첫 진찰보다 늦게 함 | ×0.85 | 감염관리는 모든 진찰에 선행해야 한다 |
| 진찰 순서 위반 | ×0.9 | 복부는 청진 → 타진 → 촉진 순. 만지면 장음이 바뀐다 |
| 준비 동작 누락 | ×0.95 | 설명·동의, 가려주기, 자세 지시 등 |

감점 배수는 **위반 개수와 무관하게 종류당 한 번만** 곱한다. 순서를 두 군데 틀렸다고 두 번
깎지 않는다.

압통 부위는 **마지막에** 진찰해야 한다. 아픈 곳을 먼저 누르면 환자가 방어해 나머지 진찰이
부정확해지기 때문이다.

### 8.3 환자교육 — 네 가지를 설명했나

진단 설명·검사 계획·치료·합병증 네 범주를 학생이 말한 내용과 대조한다. 각 항목에는
채점 기준(good / ok / miss)이 붙어 있어 부분 점수가 나온다.

진단이 틀리면 그 위에 쌓은 설명도 함께 감점된다.

### 8.4 환자의사관계(PPI) — 6영역 34항목

CPX 평가표의 PPI 6영역을 34개 항목으로 펼쳐, 항목마다 pass / fail / **na**로 판정한다.

| 영역 | |
|---|---|
| 1 | 유대관계 형성 |
| 2 | 효율적 청취 |
| 3 | 생각·배경 파악 |
| 4 | 이해하기 쉬운 설명 |
| 5 | 체계적 면담 |
| 6 | 신체진찰 태도 |

`na` 판정이 중요하다. 예를 들어 "가려주기"는 **가릴 진찰 자체가 없는 케이스**에서는 못 한 게
아니라 **할 일이 없었던 것**이다. 이런 항목을 fail로 세면 케이스에 따라 점수가 부당하게
낮아진다. 그래서 케이스가 실제로 가진 진찰 항목을 넘겨받아 판정 대상에서 뺀다.

```
PPI 점수 = 20 × (통과 항목 수 ÷ 판정 가능 항목 수)
```

### 8.5 리포트에 무엇이 남나

점수만 주고 끝내지 않는다. 학생이 **"왜 이 점수인지"를 항목 단위로** 볼 수 있어야 연습
도구가 된다.

- 물어본 항목 / **놓친 항목** 목록
- **못 얻은 숨은 정보**와 그걸 여는 질문 예시
- 신뢰도가 오르내린 지점 (어떤 발화에서 환자가 마음을 열었나)
- 진단 근거 판정 — 맞혔더라도 근거가 부족하면 그렇게 적는다
- 진찰 항목별 시행 여부와 감점 사유

## 9. 배포 고려사항

**오프라인 동작** — 3D 메시 디코더가 기본값으로 외부 CDN에서 로드되는 구조였다. 실습실에
인터넷이 없으면 환자가 한 명도 뜨지 않으므로 전부 로컬로 옮겼고, 외부 접속을 차단한 상태에서
정상 동작을 확인했다.

**에셋 라이선스** — 전 에셋이 상업 이용 가능해야 한다. 감사 과정에서 AGPL 라이선스 에셋이
섞여 있던 것을 발견해 CC0로 교체했다. AGPL은 네트워크로 제공하는 저작물에도 소스 공개
의무가 걸려 배포에 쓸 수 없다.
